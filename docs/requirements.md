## 1. プロジェクト概要

### 1-1. 背景と目的

日本国内の文化芸術系クラウドファンディング（CAMPFIRE・Bandcamp・ENjiNE・READYFOR 等）はプラットフォームごとに分散しており、ユーザーはプロジェクトを横断的に探すことができない。また、「今どのプロジェクトが熱いか」を可視化する仕組みが存在しない。

A to B はこの課題を解決するため、複数プラットフォームのプロジェクトを一箇所に集約し、独自のヒートスコアでトレンドを可視化する比較・集約サービスを提供する。

### 1-2. サービスコンセプト

> 「支援ではなく、参加。」
> 価格.com の文化芸術版 — 複数プラットフォームを横断比較・検索できるメタプラットフォーム

### 1-3. 運営フェーズ

| フェーズ | 状態 | 収益 | 目安期間 |
|---------|------|------|---------|
| **Phase 0**（現在） | 個人プロジェクト・情報提供 | なし | 〜事業性確認まで |
| Phase 1 | 開業届提出・アフィリエイト収益化 | アフィリエイト | Phase 0 終了後 |
| Phase 2 | 法人化・有料プラン | 掲載料・プレミアム等 | Phase 1 成熟後 |

## 2. 対象ユーザー

### 2-1. プライマリユーザー（支援者）

| 属性 | 内容 |
|------|------|
| 年齢層 | 20〜40代 |
| 特徴 | 文化芸術に関心があり、支援・応援の意欲はあるが具体的な行動につながっていない |
| 課題 | どのプラットフォームに何があるかわからない／比較できない |
| 行動 | SNSで偶然見かけた情報や、メディア経由でプロジェクトを知る |

**ペルソナ A（発見したい人）**
- 音楽・アート好きの会社員、28歳
- CAMPFIREの存在は知っているが、他のサービスは知らない
- 「気になるアーティストが最近クラファンやってるらしい」と聞いてどこを見ればいいかわからない

**ペルソナ B（比較したい人）**
- 複数のプラットフォームを使い分けているコアユーザー、35歳
- 「どのプラットフォームで支援するのが一番手数料が安いか」を知りたい

### 2-2. セカンダリユーザー（アーティスト・クリエイター）

- 自分のプロジェクトが A to B に掲載されることで露出が増える
- Phase 1 以降、掲載申請・優先表示などの有料機能のターゲット

### 3-2. 機能詳細

#### F01 — プロジェクト一覧表示

| 項目 | 内容 |
|------|------|
| 表示件数 | 最大50件（ページネーションは Phase 1） |
| 表示情報 | サムネイル画像・タイトル・プラットフォーム名・ジャンル・達成率・支援者数・残り日数・ヒートスコアバッジ |
| デフォルト順 | ヒートスコア降順 |
| レスポンシブ | SP: 1列 / Tablet: 2列 / PC: 3列 |

#### F02 — フィルタ・絞り込み

| フィルタ項目 | 選択肢 |
|------------|--------|
| ジャンル | すべて / 音楽 / アート / 映像 / 演劇 / ダンス |
| プラットフォーム | すべて / CAMPFIRE / Bandcamp / ENjiNE / READYFOR |
| 並び順 | ヒート順 / 達成率順 / 終了間近 / 新着順 |

- フィルタは URL パラメータで保持（`?genre=music&sort=heat`）
- サーバーサイドで処理（Next.js Server Components）

#### F03 — ヒートスコア

**算出式:**

```
ヒートスコア = (支援額の伸び × 0.30)
             + (支援総額スコア × 0.30)
             + (達成率の伸び × 0.20)
             + (支援者数の伸び × 0.20)

各要素は 0〜100 に正規化
最終スコアは 0〜100
```

| スコア | バッジ | 意味 |
|--------|--------|------|
| 80〜100 | 🔥 赤 | 非常に熱い（急速な支援集中） |
| 50〜79 | 🧨 オレンジ | 注目を集めている |
| 0〜49 | 💧 青 | 通常 |

**更新頻度:** 日次（GitHub Actions スクレイピング実行後）

#### F04 — トレンドページ

- ヒートスコア 70 以上のプロジェクトを表示
- 1〜3位には順位バッジを表示
- ヒートスコアの算出ロジックを説明するセクションを設置

#### F05 — プロジェクト詳細ページ

| 表示要素 | 仕様 |
|---------|------|
| サムネイル | プロジェクト画像（なければジャンルアイコン） |
| 達成率バー | プログレスバー（100%超えても表示） |
| 支援者数・残り日数 | リアルタイム表示 |
| 外部リンクボタン | 「○○で支援する →」（Phase 1 以降はアフィリエイトURL） |
| PR表記 | 「※外部サービス / Phase 1 以降: アフィリエイトリンク」 |

#### F06 — 外部リンク

- 新しいタブで開く（`target="_blank" rel="noopener noreferrer"`）
- Phase 0: 直接 URL
- Phase 1: アフィリエイト経由 URL に切り替え

#### F07 — プラットフォーム比較

| 比較項目 | 内容 |
|---------|------|
| 手数料 | パーセンテージ（税込） |
| 資金調達タイプ | All-or-Nothing / Keep-it-All |
| 最低目標金額 | あり/なし |
| 対応ジャンル | テキスト説明 |
| 支援形態 | リターン型・寄付型・購入型 |

- テーブル形式（横スクロール対応）
- 各PFカードも下部に表示

#### F08 — スクレイピング自動更新

| 項目 | 内容 |
|------|------|
| 実行環境 | GitHub Actions |
| 実行頻度 | 毎日 AM 3:00 JST |
| 対象 | CAMPFIRE（Phase 0）→ 全PF（Phase 1） |
| 取得データ | 現在支援額・支援者数・達成率 |
| 更新先 | Supabase `projects` テーブル + `heat_snapshots` |
| エラー処理 | 失敗時はスキップして次のプロジェクトへ（サービス継続優先） |

## 4. 非機能要件

### 4-1. パフォーマンス

| 指標 | 目標値 |
|------|--------|
| ページ初期表示（LCP） | 3秒以内 |
| データ更新頻度 | 日次（24時間以内） |
| 同時アクセス耐性 | 100ユーザー同時（Vercel 無料プランの範囲） |

### 4-2. 可用性

| 指標 | 目標値 |
|------|--------|
| 稼働率 | 99%以上（Vercel SLA 準拠） |
| 計画メンテナンス | 事前に SNS で告知 |

### 4-3. セキュリティ

| 項目 | 対応 |
|------|------|
| DB アクセス | Row Level Security（RLS）で読み取りのみ公開 |
| 書き込み | Service Role Key のみ可（GitHub Secrets で管理） |
| 環境変数 | Vercel / GitHub Secrets で管理、コードに含めない |
| XSS 対策 | Next.js デフォルト（JSX エスケープ）で対応 |
| HTTPS | Vercel が自動対応 |

### 4-4. SEO

| 項目 | 対応 |
|------|------|
| メタタグ | 全ページに title / description を設定 |
| OGP | SNS シェア時のサムネイル・説明文 |
| 構造化データ | Phase 1 で実装（JSON-LD） |
| サイトマップ | Phase 1 で実装 |
| SSR / SSG | Next.js App Router で対応済み |

### 4-5. アクセシビリティ

| 項目 | 対応 |
|------|------|
| 文字サイズ | 最小 12px |
| コントラスト比 | WCAG AA 準拠（4.5:1 以上） |
| alt テキスト | 画像要素に設定 |
| aria ラベル | ボタン・リンクに設定 |

### 4-6. コスト制約

| サービス | 月額 | 備考 |
|---------|------|------|
| Vercel | 無料 | Hobby プラン |
| Supabase | 無料 | 500MB・50,000行まで |
| GitHub Actions | 無料 | パブリックリポジトリ |
| Cloudflare + ドメイン | 〜125円/月 | 年1,500円 |
| **合計** | **〜125円/月** | |

## 5. システム構成

### 5-1. アーキテクチャ

```
[外部PF 公開ページ]
  CAMPFIRE / Bandcamp / ENjiNE / READYFOR
        ↓ スクレイピング（Python）
        ↓ GitHub Actions（毎日 AM 3:00）

[Supabase（PostgreSQL）]
  projects / platforms / artists
  heat_snapshots / platform_comparisons
        ↓ REST API（anon key）

[Next.js 14 / Vercel]
  Server Components で SSR/SSG
  App Router（/projects /trending /compare /privacy /terms）
        ↓

[ユーザーブラウザ]
```

### 5-2. 技術スタック

| 層 | 技術 | バージョン |
|----|------|-----------|
| フロントエンド | Next.js | 14.1.0 |
| スタイリング | Tailwind CSS | 3.3+ |
| 言語 | TypeScript | 5+ |
| ホスティング | Vercel | - |
| データベース | Supabase（PostgreSQL） | - |
| スクレイピング | Python + BeautifulSoup4 | 3.11 |
| CI/CD | GitHub Actions | - |
| DNS / ドメイン | Cloudflare | - |

## 7. データ定義

### 7-1. テーブル一覧

| テーブル名 | 説明 |
|-----------|------|
| `platforms` | プラットフォームマスタ（CAMPFIRE 等） |
| `artists` | アーティスト・クリエイター情報 |
| `projects` | プロジェクト情報（メインテーブル） |
| `heat_snapshots` | ヒートスコア日次履歴 |
| `platform_comparisons` | プラットフォーム比較データ |

詳細スキーマ: [`webapp/supabase/schema.sql`](../webapp/supabase/schema.sql)

### 7-2. ヒートスコアの保持ルール

- 日次スナップショットとして `heat_snapshots` に蓄積
- 当日スコアは `projects.heat_score` に反映
- 履歴は 90日間保持（Phase 1 以降にトレンドグラフ機能で活用）

## 9. 制約条件

| 区分 | 制約 |
|------|------|
| **法的** | Phase 0 は個人プロジェクト（収益なし）。収益化前に開業届提出が必要 |
| **著作権** | 掲載プロジェクト画像は各PFの公開画像を引用元リンク付きで使用 |
| **スクレイピング** | 各PFの robots.txt・利用規約の範囲内で実施。1.5秒以上の間隔を保持 |
| **コスト** | 月額 1,500円以下を維持（Phase 0） |
| **開発体制** | Phase 0 は AI 生成コードを活用。CTO 採用は Phase 2 以降 |

## 10. スコープ外（やらないこと）

Phase 0 では以下は対象外とする:

- クラウドファンディングの実施機能（資金調達・リターン管理）
- ユーザー登録・ログイン機能（Phase 1 で追加）
- 決済機能
- アーティスト向け管理画面
- リアルタイムデータ更新（日次で十分）
- 多言語対応
- アプリ（iOS / Android）
